# 标签打印工作台效率功能与冗余代码清理设计

## 背景

当前线上版本与 `codex/print-workflow-improvements` 分支一致，已经包含打印方向、字号预览、数量步进、最近标签和工作区布局等较新的能力。另一个已分叉的历史分支 `deploy/github-cloudflare` 包含搜索、撤销/重做、键盘快捷键和记录剪贴板等效率功能，但缺少现有分支中的部分新功能，因此不能直接合并整个分支。

本次工作以当前线上对应分支为唯一基线，选择性迁移高价值功能，并清理已经确认没有运行时调用的旧接口。目标是提高批量编辑效率，同时不改变现有打印结果、草稿兼容性和线上数据结构。

## 目标

1. 支持按标签主要文本内容快速筛选记录。
2. 支持可撤销、可重做的主要编辑操作，并提供按钮与常见快捷键。
3. 支持复制、剪切和粘贴选中的标签记录。
4. 提供快捷键帮助入口，让功能可发现。
5. 删除能够通过引用检查和测试证明为运行时冗余的旧函数与未使用导入。
6. 保持当前分支已有打印、字号、数量、最近标签、导入和工作区行为不变。

## 非目标

- 不整体合并 `deploy/github-cloudflare` 分支。
- 不在本次加入云同步、账号、导出备份、打印机校准或新的数据格式。
- 不重做现有视觉风格和页面布局。
- 不删除仍存在于草稿或本地存储结构中的兼容字段，例如 `stylePresets`、`recentSizes`、`verticalAlign`、`paperSize`。
- 不自动推送远程仓库或部署到 Cloudflare Pages。

## 方案选择

### 采用：选择性迁移并按当前架构适配

从历史分支提取领域逻辑、组件和测试意图，在当前分支上重新适配。这样可以保留现有打印工作流，避免分支级合并带来的功能倒退和冲突扩散。

### 未采用：直接合并历史分支

两个分支均有独立演进，直接合并会把旧版应用结构与新版打印功能混在一起，冲突面大，且容易覆盖现有行为。

### 未采用：从零重写效率功能

已有分支提供了可验证的实现和测试参考。完全重写会增加不必要的设计偏差和回归风险。

## 功能设计

### 1. 记录搜索

- 新增独立的搜索领域函数，输入标签集合和查询词，输出匹配记录。
- 查询忽略首尾空格和大小写。
- 匹配范围为 `LabelRecord.content`，忽略大小写但保留中文原义；空查询显示全部记录。
- 搜索只影响列表展示，不修改原始标签集合、选中状态或打印队列。
- 搜索框显示清除操作和匹配数量；无结果时显示明确空状态。

### 2. 撤销与重做

- 使用有限长度的历史栈保存可逆的工作台状态快照。
- 业务类型、用途、标签内容、数量、尺寸、样式、排序、添加、删除、导入、粘贴和工作区布局调整进入历史。
- 活动记录切换、选择集、搜索词、弹窗开关、帮助面板、打印旋转、最近标签记录和上次打印尺寸不作为独立撤销步骤；这些非历史更新同步应用到历史快照，避免撤销时回滚辅助状态。
- 新编辑发生后清空重做栈。
- 没有可撤销或可重做状态时，按钮保持禁用。
- 快捷键为 `Ctrl+Z` 撤销、`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做；输入法组合期间不触发。

### 3. 记录复制、剪切与粘贴

- 复制对象优先取当前选中的完整标签记录；没有多选时使用活动记录；两者都不存在时相关操作禁用。
- 使用应用内剪贴板保存结构化记录，不依赖系统剪贴板权限。
- 复制模式粘贴时生成新的唯一 ID，保留内容、数量、尺寸和样式；新记录插入活动记录之后，没有活动记录时追加到末尾，并把新记录设为活动和选中状态。
- 剪切不会立即删除来源记录，而是标记待移动状态；粘贴时把来源记录作为一个可撤销动作移动到活动记录之后，按 `Escape` 可取消待移动状态。
- 连续粘贴始终生成新记录，不复用原 ID。
- 复制和进入剪切待移动状态不进入撤销历史；实际粘贴或移动进入历史。

### 4. 快捷键与帮助

- 在应用级键盘监听器中统一处理撤销、重做、复制、剪切、粘贴和帮助快捷键；Windows/Linux 使用 `Ctrl`，macOS 使用 `Command`。
- 当焦点位于文本输入、文本区域、可编辑元素或组合输入状态时，不拦截原生复制、剪切、粘贴和撤销行为。
- 提供可访问的快捷键帮助对话框，列出当前实际支持的组合键。
- 按钮、菜单项和帮助内容使用一致文案，并提供 `aria-label` 或可见标签。

## 架构与组件边界

### 领域层

- `src/domain/labelSearch.ts`：纯函数搜索与字段归一化。
- `src/domain/draftHistory.ts`：历史栈状态、提交、撤销和重做。
- `src/domain/workspaceClipboard.ts`：记录快照复制与安全克隆。
- `src/domain/shortcutKeys.ts`：快捷键识别和输入上下文保护。

这些模块不依赖 React 或浏览器 DOM，便于单元测试。已有领域模块仍负责草稿、打印布局、尺寸和持久化，不把效率功能逻辑塞入其中。

### 视图层

- `src/features/RecordSearch.tsx`：搜索输入、清除和结果计数。
- `src/features/ShortcutHelpDialog.tsx`：快捷键说明对话框。
- `src/App.tsx`：组合历史状态、筛选结果、选中记录和剪贴板命令。
- `src/styles.css`：只补充新控件所需样式，沿用现有设计变量和响应式规则。

如果 `App.tsx` 的新增协调逻辑过长，可提取一个聚合快捷键 Hook，但不会借本次机会进行无关重构。

## 数据流

1. 持久化层加载草稿，生成当前工作台状态。
2. 用户编辑通过统一提交入口产生下一个草稿状态，并写入历史栈。
3. 搜索词在视图层筛选当前标签，原始状态保持完整。
4. 复制把选中记录克隆到应用内剪贴板；剪切和粘贴通过统一提交入口改变草稿。
5. 撤销或重做替换当前草稿状态，再沿用现有持久化机制保存。
6. 顶部“预览并打印”仍读取完整草稿和既有打印配置；单条记录的打印入口仍只预览活动记录。搜索结果不会改变两种打印范围。

## 错误与边界处理

- 空查询、空选中、空剪贴板和空历史栈均为正常状态，不抛异常。
- 对历史分支中可能不符合当前类型定义的旧记录先经过当前草稿规范化函数。
- 粘贴时重新生成 ID，避免 React key 和记录更新冲突。
- 快捷键不会覆盖输入框内的浏览器原生编辑行为。
- 搜索无结果时仍可清除查询并恢复全部记录。
- 历史栈设置固定上限，避免长时间编辑造成内存无限增长。

## 冗余代码清理

删除范围只包含经过全仓引用检查后确认没有生产调用、且已有替代实现的导出：

- `src/domain/images.ts` 中被 `recognizeImageLayout` 取代的 `recognizeImage`。
- `src/domain/importing.ts` 中只被旧测试直接调用的 `rowsToLabels`。
- `src/domain/layout.ts` 中只被旧测试直接调用的 `solveTextLayout`。
- `src/domain/workspaceLayout.ts` 中被 `placeWorkspacePanel` / `moveWorkspacePanel` 取代的 `reorderWorkspacePanels`。
- `src/domain/draft.ts` 中未使用的 `validateSizePreset` 导入。

若某个函数在迁移后的代码或有效测试中仍有必要，则保留并记录原因，不为满足“清理”数量而删除。相关旧测试应改为验证公开替代接口，而不是保留只为测试存在的生产导出。

## 测试策略

### 单元测试

- 搜索：空查询、大小写、空格、多字段、无结果、不修改输入。
- 历史：提交、撤销、重做、新编辑清空重做栈、历史上限、不可变性。
- 剪贴板：复制克隆、剪切语义、粘贴新 ID、多次粘贴。
- 快捷键：支持组合键、输入控件保护、组合输入保护、不同平台修饰键。
- 被删除旧接口：把测试迁移到对应公开替代接口，并确保覆盖不下降。

### 组件与集成测试

- 搜索输入能够筛选、清除并恢复记录。
- 撤销/重做按钮状态和快捷键符合历史状态。
- 复制、剪切、粘贴对选择集和记录数量产生预期变化。
- 文本输入中的原生快捷键不被应用拦截。
- 帮助对话框可通过键盘打开、关闭并正确管理焦点。
- 现有打印方向、字号、数量、最近标签、Excel 导入及无障碍测试继续通过。

### 验证命令

- `pnpm typecheck`
- `pnpm test`
- `pnpm build`
- 对构建后的页面进行浏览器交互验证；至少覆盖搜索、撤销/重做、剪切/粘贴和打印预览不回归。

## 验收标准

1. 用户可在不修改记录的前提下搜索和清除筛选。
2. 主要记录编辑可通过按钮和快捷键撤销、重做。
3. 用户可复制、剪切和多次粘贴记录，所有新记录 ID 唯一。
4. 快捷键在文本编辑场景不破坏浏览器原生行为。
5. 快捷键帮助内容与实际行为一致且可键盘访问。
6. 现有全部自动化测试通过，TypeScript 类型检查和生产构建成功。
7. 严格未使用检查不再报告 `validateSizePreset`，已列出的冗余接口不再存在生产代码中。
8. 本地验证完成后不自动部署，由用户决定是否推送和发布。

## 实施顺序约束

实施计划应按测试驱动方式拆分：先为领域逻辑写失败测试，再实现领域模块；随后加入组件和集成测试并接入 `App.tsx`；最后清理冗余接口、运行全量验证和浏览器检查。每一步都以当前分支既有行为为回归基线。
