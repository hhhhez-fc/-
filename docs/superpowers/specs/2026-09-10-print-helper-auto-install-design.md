# 打印助手自动唤起、下载与发布设计

**日期：** 2026-09-10

**状态：** 待用户审阅
**适用项目：** 唛头打印工作台与 Windows Label Print Helper

## 1. 目标

当用户明确点击“检查并打印”进入直接打印流程时，网站自动完成以下编排：

1. 检测本机打印助手；
2. 未连接时自动尝试唤起已安装的打印助手；
3. 等待后仍未连接时，自动安排下载与网站版本匹配的安装包；
4. 安装期间持续检测，助手上线后继续现有配对、打印机选择和校准流程；
5. 安装包通过 GitHub Releases 发布，网站部署到现有 Cloudflare Pages 地址。

浏览器不能、也不得静默安装 Windows 可执行文件。这里的“自动安装流程”指自动唤起、一次性自动下载、清楚指导用户运行安装程序，以及安装后自动恢复连接；Windows 安装确认仍由用户完成。

## 2. 已确认约束

- 只在用户点击“检查并打印”后启动自动流程，不在普通访问网站时弹协议或下载文件。
- 首个支持平台保持为 Windows x64、Xprinter XP-420B、203 DPI、`100 × 75 mm` 标签。
- 正常直接打印仍不打开浏览器打印窗口。
- 打印助手安装包托管在当前 GitHub 仓库的 Releases，不提交大型二进制文件到 Git 仓库。
- 网站继续托管在 `https://label-printing-workbench.pages.dev/`。
- 每个助手版本使用固定、不可变的 Release 下载地址和 SHA-256；网站不依赖可漂移的 `latest` 重定向判断版本。
- 未经签名的安装包必须如实标记为测试版本，不得伪装成已签名或已完成实体打印机生产验收。

## 3. 采用方案

采用“GitHub Release 版本化安装包 + Pages 静态版本清单”。

网站随构建发布一份小型 JSON 清单，包含助手版本、协议版本、固定下载地址、文件名、SHA-256 和 Release 说明地址。安装包本身保存在 GitHub Release。这样网站能展示可核对的版本与哈希，同时避免把约 100 MB 以上的安装包加入网页仓库。

不采用以下方案：

- 直接使用 `releases/latest/download/...`：地址会漂移，网页无法稳定展示与文件一一对应的哈希。
- 把安装包放入 Vite `public/`：会扩大仓库与每次部署体积，并增加静态部署失败风险。
- 访问页面即下载：会造成意外下载、浏览器拦截和用户不信任。

## 4. 网站交互与状态机

### 4.1 触发条件

现有应用启动时的只读健康检查保留。自动唤起与下载只能由用户点击“检查并打印”触发；该点击为整个流程的用户意图来源。

如果打开直接打印对话框时助手已经连接，网站直接显示现有打印机与校准界面，不触发协议或下载。

### 4.2 自动唤起

如果状态为“未检测到打印助手”，网站立即调用一次 `labelprint://start`，并把界面状态改为“正在启动打印助手”。同一次对话框生命周期内不得重复唤起，防止外部协议确认框循环出现。

网站在唤起后按 `0、1.5、3、5` 秒进行有界健康检查。任一次连接成功即取消剩余检查和待执行下载。

### 4.3 自动下载

唤起后 5 秒仍未连接时，网站进入“需要安装打印助手”状态，并针对清单中的当前版本自动发起一次安装包下载。

- 自动下载按“浏览器会话 + 助手版本”去重，使用版本化 `sessionStorage` 标记；关闭并重新打开对话框不会重复下载。
- 浏览器拒绝自动下载时，界面必须持续显示“下载安装包”按钮，不能只依赖自动行为。
- 用户主动点击“重新下载”不受会话去重限制。
- 版本不兼容时直接进入同一下载/更新状态，不反复唤起旧版本助手。
- 下载动作不携带业务标签、配对令牌、打印机名称或其他用户数据。

### 4.4 安装等待与恢复

安装卡片显示：

- 安装包文件名与版本；
- SHA-256；
- “已安排下载”或“浏览器可能拦截了下载”的明确状态；
- “下载安装包”“复制 SHA-256”“已安装，立即检测”操作；
- 说明用户仍需打开 EXE 并完成 Windows 安装提示。

下载开始后，只要对话框保持打开，网站每 2 秒检测一次助手，最长 120 秒。对话框关闭、组件卸载或检测成功时必须取消计时器和请求。超时后停止自动请求，保留“重新检测”按钮。

助手上线后：

1. 如果需要配对，进入现有配对确认状态；
2. 如果已配对，读取 Windows 打印机队列；
3. 未连接 XP-420B 时显示现有“未发现可用且兼容的 XP-420B”；
4. 打印机存在但未校准时继续现有校准与实体边框确认；
5. 全部通过后启用“直接打印”。

### 4.5 对话框呈现

保留现有工业工作台视觉语言和一个主打印对话框，不叠加新的浏览器弹窗。助手区域改为紧凑的四阶段进度：

`启动助手 → 安装/连接 → 网站配对 → 打印机校准`

当前阶段使用文字、图标和颜色共同表达；状态更新进入现有 `aria-live` 区域。按钮在忙碌时保持尺寸稳定。键盘焦点、Escape 关闭、背景 inert/focus trap 和关闭后焦点恢复沿用现有对话框契约。

## 5. 版本清单

网站公开文件：`public/print-helper/latest.json`

```json
{
  "schemaVersion": 1,
  "helperVersion": "0.1.0",
  "protocolVersion": 1,
  "platform": "windows-x64",
  "fileName": "LabelPrintHelper-Setup.exe",
  "downloadUrl": "https://github.com/hhhhez-fc/-/releases/download/print-helper-v0.1.0/LabelPrintHelper-Setup.exe",
  "sha256": "<64 lowercase hex characters>",
  "releaseNotesUrl": "https://github.com/hhhhez-fc/-/releases/tag/print-helper-v0.1.0",
  "publishedAtUtc": "<ISO-8601 UTC>"
}
```

应用构建时校验清单结构。下载地址必须为当前仓库的 HTTPS GitHub Release 地址，哈希必须为 64 位小写十六进制，协议版本必须与网页客户端支持版本一致。清单请求失败或校验失败时不自动跳转未知地址，只显示安全错误与稍后重试。

## 6. 安装包构建与 GitHub Release

新增仅在 Windows Runner 执行的 GitHub Actions 工作流：

1. 检出明确提交；
2. 安装项目声明的 .NET 10 SDK；
3. 运行全部打印助手测试；
4. 安装 Inno Setup 6 编译器；
5. 使用现有 `print-helper/scripts/build-installer.ps1` 生成自包含 x64 安装包；
6. 运行安装器契约检查并计算 SHA-256；
7. 生成 Release 校验文件；
8. 使用 `print-helper-v<version>` 标签创建 GitHub Release，上传安装包与校验文件。

工作流权限限制为发布所需的 `contents: write`，其他权限保持只读或关闭。Release 上传失败时不得更新网站版本清单。

安装器版本必须与 Release 标签一致；不一致时构建失败。后续版本发布顺序固定为：先产生并验证 Release 资源，再更新网站清单并部署 Pages。这样线上页面不会指向尚不存在的安装包。

## 7. 安全和隐私

- 自动流程只访问 `https://localhost:17653/v1/health`、已批准的本机助手端点和固定 GitHub Release 下载地址。
- 下载 URL、协议 URL 和版本清单不可由标签内容或查询参数控制。
- 配对令牌继续使用现有版本化本地存储，不写入 URL、日志、下载请求或界面截图。
- SHA-256 用于完整性核对，不替代代码签名。没有代码签名证书时，界面和发布说明必须明确标注发布者验证限制。
- 不要求用户绕过 Windows SmartScreen、证书错误或浏览器安全警告；遇到无法验证的发布者应停止安装并联系维护者。
- 自动下载失败不会回退到浏览器打印；紧急浏览器打印入口保持独立、明确标记。

## 8. 代码边界

计划新增或修改的职责边界：

- `src/services/printHelperInstaller.ts`：读取并验证清单、触发下载、会话去重；不管理 React 状态。
- `src/features/usePrintHelperBootstrap.ts`：管理自动唤起、定时检测、取消和状态机；不渲染 UI。
- `src/features/PrintReviewDialog.tsx`：呈现进度、安装卡片和人工恢复操作。
- `src/features/usePrintHelper.ts`：继续负责助手 API、配对、打印机与校准状态；不承担下载职责。
- `src/services/printHelperLaunch.ts`：继续只负责固定的 `labelprint://` 协议目标。
- `public/print-helper/latest.json`：线上版本与完整性清单。
- `.github/workflows/release-print-helper.yml`：可复现构建、测试、哈希和 Release 上传。
- `print-helper/installer/LabelPrintHelper.iss` 与构建脚本：统一版本注入并阻止标签/安装器版本漂移。

## 9. 错误处理

- 助手启动但版本不兼容：显示更新安装卡，不继续配对或打印。
- 清单不可用或不合法：停止自动下载，显示“暂时无法获取经过验证的安装包”，允许重试。
- 浏览器阻止协议：等待阶段结束后进入下载卡，不循环弹协议。
- 浏览器阻止下载：保留人工下载按钮并提示检查下载栏；不声称下载已成功。
- 用户取消安装或安装超时：停止自动轮询，保留当前编辑和打印设置。
- 助手中途连接：立即取消后续下载/检测，进入配对或 ready 状态。
- 对话框关闭或页面卸载：中止所有挂起请求与计时器，不在后台继续下载。

## 10. 验证与上线门槛

### 网站自动化测试

- 已连接时不唤起、不下载；
- 未安装时每次对话框只唤起一次；
- 5 秒内连接会取消下载；
- 5 秒后每个版本、每个会话只自动下载一次；
- 自动下载受阻时人工按钮仍可用；
- 版本不兼容进入更新流程；
- 清单 URL、哈希或协议版本非法时拒绝下载；
- 关闭对话框会取消轮询；
- 安装后自动进入配对/ready；
- 键盘、状态播报和窄屏布局保持可用。

### 打印助手与发布验证

- 全部 .NET 测试通过；
- 安装包可在干净的 Windows x64 用户环境完成安装、登录启动、`labelprint://start` 唤起和卸载；
- 安装包实际 SHA-256 与网站清单及 Release 校验文件完全一致；
- Release 固定地址返回安装包而非 HTML 错误页；
- 网页测试、无障碍测试、TypeScript 类型检查和生产构建全部通过；
- Cloudflare Pages 线上 JS/CSS/清单与已验证构建一致；
- 线上使用真实浏览器验证自动唤起、仅一次下载、安装后自动连接和配对。

实体 XP-420B 的 `100 × 75 mm` 单张边框、传感器和连续打印仍是生产直接打印的独立硬件门槛。没有实体通过记录时，可以上线自动安装流程，但必须保留“尚未完成实体生产验收”的发布风险说明。

## 11. 上线与回滚

上线顺序：

1. 创建并验证 GitHub Release；
2. 更新清单为该 Release 的固定地址和真实哈希；
3. 构建并推送网站版本；
4. 等待 Cloudflare Pages 部署完成；
5. 在线验证清单、安装包下载和助手连接状态。

回滚时只需把网站清单和前端代码回退到上一个已验证版本；已有不可变 Release 不删除，以保证旧网页仍可恢复。发现安装器安全问题时应撤下对应 Release 并让网站清单立即停止指向它，而不是静默复用同一版本号替换二进制文件。
