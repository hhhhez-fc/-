# 唛头打印工作台 GitHub 与公网部署设计

## 目标

把当前只能通过 `http://127.0.0.1:5173/` 使用的 Vite 应用发布为固定的 HTTPS 公网网站，使任何人都能在任意电脑的现代浏览器中打开并工作。同时把完整项目纳入 Git 版本控制并上传到 GitHub，后续代码更新可自动部署。

## 已确认的产品约束

- 网站无需登录，知道网址的人都可以打开。
- 每台电脑、每个浏览器配置文件独立保存草稿，不跨设备共享。
- Excel、图片、OCR 内容和草稿继续在浏览器本地处理，不上传到应用服务器。
- 不增加后端、数据库、账号系统或云同步。
- 首次使用免费托管地址；正式地址使用 Cloudflare Pages 提供的 `*.pages.dev` HTTPS 子域名。
- 使用用户指定的 GitHub 仓库 `https://github.com/hhhhez-fc/-.git`；网站本身公开访问。

## 推荐架构

代码保存在 GitHub 私有仓库中，Cloudflare Pages 连接该仓库的默认分支。每次向默认分支推送提交时，Cloudflare 自动安装依赖、执行生产构建并发布 `dist` 目录。

```text
开发电脑
  └─ Git 提交并推送
       └─ GitHub 私有仓库
            └─ Cloudflare Pages 自动构建
                 └─ 固定 HTTPS 公网地址

访问者浏览器
  ├─ 下载静态网页资源
  ├─ 本地解析 Excel / 图片 / OCR
  ├─ localStorage 保存该浏览器自己的草稿
  └─ 调用浏览器打印功能
```

Cloudflare 的构建设置为：

- 框架：React / Vite。
- 安装方式：依据仓库中的 `pnpm-lock.yaml` 使用 pnpm。
- 构建命令：`pnpm build`。
- 构建输出目录：`dist`。
- 生产分支：`main`。

## GitHub 版本控制设计

在当前项目目录初始化 Git 仓库，默认分支命名为 `main`。提交前新增适合 Vite、Node.js、编辑器缓存和本地环境文件的 `.gitignore`，确保以下内容不进入仓库：

- `node_modules/` 与生产构建目录 `dist/`。
- 本地环境变量文件和部署凭据。
- 测试覆盖率、日志、临时文件和常见编辑器缓存。

首次提交包含当前应用源码、测试、设计文档、依赖锁文件和部署配置。把用户指定的 `https://github.com/hhhhez-fc/-.git` 设置为 `origin`，推送 `main` 并验证远端提交与本地一致。若远端已有提交，先读取并比较历史，不覆盖或强制推送。

## 数据、隐私与浏览器边界

网站部署的是静态资源，不提供接收业务文件的服务器接口。当前代码中的 `localStorage` 键保持不变，因此：

- 同一电脑的同一浏览器配置文件刷新后可以恢复草稿。
- 换电脑、换浏览器或使用无痕窗口时不会看到之前的草稿。
- 清理浏览器网站数据会删除草稿。
- 浏览器本地存储空间不足时，现有“无法保存草稿”提示继续生效。

公开网站意味着任何知道地址的人都能加载应用程序，但看不到其他人的本地草稿或导入文件。仓库和部署配置不得包含 GitHub、Cloudflare 或其他服务的令牌。

## 发布与更新流程

首次发布流程：

1. 在本机运行测试和生产构建。
2. 初始化 Git、创建首次提交并推送至 GitHub 私有仓库。
3. 在 Cloudflare Pages 中授权读取该 GitHub 仓库。
4. 配置构建命令和输出目录，触发首次部署。
5. 记录并打开生成的固定 `*.pages.dev` 地址。
6. 在该公网地址完成导入、保存、刷新恢复和打印验证。

后续更新只需在本机完成修改、测试、提交并推送至 `main`；Cloudflare Pages 自动发布新版本。构建失败时继续保留上一版成功部署，不把失败版本切换到生产地址。

## 错误处理

- GitHub CLI 未登录时，暂停在登录授权步骤，不把凭据写入项目文件。
- Cloudflare 未登录或未授权仓库时，通过官方登录页面完成一次性授权。
- 远端仓库不存在或当前账号无写入权限时，停止推送并通过 GitHub 官方登录流程完成授权。
- 构建或测试失败时停止上传或部署，保留失败输出用于修复。
- 公网部署成功但页面无法加载时，检查构建输出、资源路径和 Cloudflare 部署日志。
- 某些网络无法访问 `pages.dev` 时，保留绑定自有域名或迁移托管平台的后续选项；本次不购买域名。

## 验证与验收

本地验证：

- `pnpm test` 全部通过。
- `pnpm build` 完成且生成 `dist/index.html`。
- 使用生产构建预览检查页面可加载且无明显控制台错误。

公网验证：

- 使用生成的 HTTPS 地址从非开发服务器端口访问应用。
- 导入示例 Excel，并确认内容与数量解析正常。
- 新增或修改草稿，刷新页面后确认该浏览器能恢复。
- 在另一浏览器或无痕窗口打开，确认不会共享草稿。
- 检查图片导入与 OCR 仍在浏览器中工作。
- 打开打印预览，确认纸张尺寸、页数和内容没有因公网部署改变。
- 确认 GitHub 仓库的实际可见性符合用户现有设置、`main` 已推送，Cloudflare 部署来源指向正确提交。

## 不包含的范围

- 用户账号、访问权限控制和内部员工身份认证。
- 多电脑草稿同步、多人协作和云端数据备份。
- 自有域名购买、ICP备案或中国大陆境内 CDN。
- 自动读取本机打印机、静默打印或远程控制打印机。

## 完成标准

项目完整保存在用户指定的 GitHub 仓库；Cloudflare Pages 从该仓库自动构建并提供固定 HTTPS 公网地址；任何电脑都可以打开并使用应用；业务文件和草稿仍只存在于各自浏览器；本地测试、生产构建和公网核心流程验证全部通过。
