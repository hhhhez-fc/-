# 可调整工作台与使用记录设计规格

## 目标

在保持“所有数据只保存在当前浏览器”的前提下，让操作员可以按自己的工作习惯调整工作台板块、减少重复确认步骤，并把真正打印过的唛头作为可复用历史保存。图片导入仍由用户决定何时识别；使用原图时，记录名称来自整图内容而不是文件名。

## 已确认的产品决定

- 工作台包含“录入来源、尺寸与预览、校对清单、使用过的唛头”四个板块。
- 拖动板块标题栏改变板块顺序；板块自动吸附到网格，不允许互相覆盖。
- 不显示调整大小按钮。桌面端在板块右边界、下边界和右下角直接拖动宽度或高度；窄屏固定全宽，只调整高度。
- 板块顺序和尺寸保存在当前浏览器，每台电脑互相独立。
- 自动排列下拉选择后立即生效，不再需要“全部自动排列”按钮。
- 删除逐条“确认校对完成”按钮和人为校对门槛；内容、数量、尺寸、越界、重叠等客观错误仍阻止打印。
- 点击实际的分尺寸打印按钮时，把本次打印包含的唛头快照写入“使用过的唛头”。相同快照重复打印时更新最近使用时间和次数。
- 选择图片后不自动 OCR。点击“识别文字”仍识别用户框选范围；点击“使用原图”时才自动识别整图全部内容，原图仍用于预览和打印，识别文字用于记录名称和历史检索。

## 工作台布局

### 板块模型

工作台布局使用四个稳定板块 ID：`intake`、`preview`、`records`、`history`。本地草稿增加布局字段：

- `panelOrder`：四个板块 ID 的完整排列。
- `panelSizes`：每个板块的桌面宽度和高度。

旧草稿没有布局字段时使用默认值：录入来源、尺寸与预览、校对清单在第一排，使用过的唛头排在下一位置；预览默认最宽。读取草稿时过滤未知或重复 ID，并补齐缺失板块，防止旧数据或损坏数据让板块消失。

### 排序交互

- 标题栏是拖动入口，指针移动超过 4px 才开始排序，普通点击不会移动板块。
- 拖过另一板块中心时交换顺序；放开后立即保存。
- 拖动中显示当前板块和目标位置，不创建自由悬浮坐标，也不允许覆盖。
- 键盘等价操作使用标题栏焦点配合 `Alt+方向键` 前移或后移板块。

### 调整大小

- 板块右侧、底部和右下角各有一条透明边界命中区，不显示按钮或常驻图标。
- 光标进入命中区后分别显示水平、垂直或对角调整光标；拖动期间显示边界强调。
- 边界使用可聚焦的 `separator` 语义，并支持方向键调整，`Shift` 加速，保证无鼠标时仍可操作。
- 桌面宽度限制在 220–900 px，高度限制在 320–1200 px；内容超过用户设置高度时在板块内部滚动。
- 720 px 以下板块强制全宽，忽略保存的桌面宽度，只应用高度，页面不得出现横向溢出。

## 自动排列

“自动排列方式”保留原生选择器，选项为水平居中、左对齐、右对齐、保持当前左右位置。`change` 事件直接对所有非空文字行执行排列：单行垂直居中，多行上下均匀分布；空行不改变位置。删除独立应用按钮，焦点留在选择器中，预览和草稿同步更新。

## 校对与打印验证

校对清单继续承担内容编辑、复制、删除和批量样式设置，但不再存在 `needsReview` 造成的用户确认门槛：

- 删除“确认校对完成／已完成校对”按钮、待校对计数和待校对徽标。
- 编辑内容或数量后立即保存，不产生“请重新校对”状态。
- 打印计划仍检查空内容、图片不可用、数量、张贴面数、尺寸预设、文字越界和文字重叠。
- 打印检查对话框继续列出所有客观错误，并允许返回对应记录修改。
- 旧草稿中的 `needsReview` 和 `reviewReason` 可被读取但不再参与界面或打印判断；保存后的新数据不依赖这两个字段。

## 使用过的唛头

### 历史数据

草稿增加 `usedLabels`，每项包含：

- 独立历史 ID。
- 完整唛头快照，包括内容、图片、数量、尺寸、打印区域、每行位置和样式。
- `lastUsedAt` ISO 时间。
- `useCount` 使用次数。

历史指纹由会影响打印结果的字段生成，排除当前记录 ID、历史 ID 和时间。再次打印相同结果时不新增条目，只更新时间与次数并移到最前。最多保存最近 50 条，超出后移除最旧条目。

### 记录时机与复用

- 只有点击打印检查对话框中的实际分尺寸打印按钮时才记录；仅打开打印检查不记录。
- 同一打印组包含多份同一记录时只记一次。
- “使用过的唛头”板块按最近使用时间排列，显示内容摘要、尺寸、最近使用时间和次数。
- “再次使用”复制历史快照为新的当前记录，生成新记录 ID并选中；历史本身不被修改。
- 历史与草稿一样完全保存在当前浏览器，不上传、不跨电脑同步。

## 图片导入

### 用户触发规则

- 文件选择只读取本地预览并进入待处理队列，不启动 OCR。
- “识别文字”继续识别当前框选区域并生成文字唛头。
- “使用原图”启动一次整图 OCR；处理期间按钮显示进度并允许取消。

### 使用原图的数据结果

- 打印内容类型保持 `image`，预览和打印继续使用原图并以 `contain` 完整显示。
- 整图 OCR 使用中英文语言包，保留识别到的中文、英文、数字、空格、连接号和换行，不再要求出现“唛头”标记，也不截取标记后的局部数据。
- OCR 全文写入记录的 `content`，用于清单摘要、历史名称和再次使用；文件名绝不写入唛头内容。
- OCR 没有返回可用文字或资源不可用时仍导入原图，`content` 使用“原图唛头”，并显示非阻断状态说明。
- 原图与 OCR 都只在当前浏览器处理和保存。

## 组件与数据流

- `App` 负责四个板块的组合、打印触发和历史记录动作。
- 新的工作台布局组件负责板块排序、边界缩放和键盘等价操作，只通过布局补丁更新草稿。
- `draftReducer` 负责布局迁移、历史去重、上限、再次使用以及移除旧校对门槛。
- `ImageImporter` 负责明确的用户触发；整图 OCR 复用图片领域函数，但使用“保留全部内容”选项。
- `SizeStylePanel` 在选择器变化时直接提交排列后的文字行。
- `LabelEditor` 删除确认动作，只保留编辑、复制和删除。

## 错误处理与安全

- 布局拖动或缩放被取消时保留上一个有效布局；非法尺寸在 reducer 中钳制。
- 本地存储空间不足时保持当前会话可用并显示持久提示，不静默丢弃正在编辑的记录。
- OCR 取消后图片仍留在队列；OCR 失败时使用原图仍可完成。
- 历史再次使用创建深拷贝，避免修改当前记录时同时修改历史快照。
- 清空草稿会同时清空本机历史和自定义布局，继续使用现有应用内确认框。

## 测试与验收

- reducer 测试覆盖布局默认值、损坏布局修复、排序、尺寸钳制、历史去重、50 条上限和再次使用深拷贝。
- 领域测试覆盖打印计划不再因旧校对状态阻断，以及整图 OCR 保留全部中英文内容。
- 组件测试覆盖：无确认按钮、无自动排列按钮、选择后即时排列、四个板块、历史再次使用、使用原图不采用文件名。
- 真实浏览器桌面验证标题栏拖动、边界光标、宽高调整与刷新后恢复；窄屏验证单列、全宽和无横向溢出。
- 真实浏览器验证选择图片不会自动 OCR，点击使用原图才运行整图 OCR。
- 完整测试、TypeScript 构建、严格产品审计和 `DESIGN.md` 校验必须通过后才能发布。

## 完成标准

操作员无需逐条确认或二次点击应用排列；可以用标题栏和板块边界定制工作台，在实际打印后从“使用过的唛头”快速复用完整结果。图片原图记录使用整图识别内容而非文件名，且所有草稿、布局、图片和历史继续由每台电脑独立保存。
